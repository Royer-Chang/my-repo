## 核心概念

### 1. 建立良好的上下文

建議先執行初始化流程，並維持 `CLAUDE.md` 的精簡與可讀性。  
圖片中特別強調：

- 先執行 `init`
- 將 `CLAUDE.md` 控制在 200 行以下
- 在第一個任務開始前，先建立清楚的專案背景與規則

這樣可以幫助 Claude 在後續對話中更準確理解專案脈絡。

### 2. 善用自動模式

圖片中指出 `Shift + Tab` 可切換至自動模式。  
啟用後，Claude 可在較少人工介入的情況下持續處理任務，適合重複性高或流程明確的工作。

### 3. 用 Agent 拆解任務

對於較大、較複雜的工作，建議交由 agent 或 subagent 分工處理：

- 主 agent：協調整體任務
- Subagent：負責局部、專注的小任務

這種模式特別適合：
- 多檔案修改
- 大型重構
- 搜尋與整理
- 測試與修復流程

## Agent / Subagent 概念

### 主 agent

主 agent 負責：
- 整體任務協調
- 上下文管理
- 工作流程控制
- 彙整各子任務結果

### Subagents

Subagent 適合：
- 處理局部且明確的工作
- 進行可獨立執行的小任務
- 背景處理或平行處理
- 減輕主 agent 的上下文負擔

### 適用情境

這種分工模式適合以下情況：
- 大型專案維護
- 多步驟修改
- 測試失敗後的修復
- 大量搜尋、分類與整理
- 有明確邊界的任務拆分

## 工具鏈與工作流程

Claude Code 不只是聊天工具，也能透過工具鏈直接協助專案工作，例如：

- 讀取檔案
- 搜尋專案內容
- 編輯程式碼
- 套用 patch
- 執行測試
- 查看 diff
- 與 git 工作流程整合

### 建議工作流程

1. 先讀取相關檔案
2. 再確認需求與上下文
3. 接著修改程式碼
4. 執行測試
5. 檢查差異
6. 修正問題
7. 再次驗證

這種流程能降低錯誤率，也能讓 Claude 更穩定地協助完成任務。

## 背景工作與離線處理

當你暫時不在 terminal 前，可以讓 Claude 在背景持續執行任務。  
這種模式適合：

- 長時間測試
- 專案掃描
- 報告整理
- 自動化處理
- 重複性維護工作

### 優點

- 不需要一直盯著畫面
- 可以節省人工操作時間
- 適合非同步工作流
- 提升大型任務處理效率

## 實務建議

圖片中傳達的最佳實務可整理如下：

### 1. 先規劃，再執行
在動手前先讓 Claude 產出計畫，避免直接修改造成混亂。

### 2. 大任務拆小任務
若任務過大，應拆分為數個可管理的小步驟，並交由 subagent 協助。

### 3. 先讀再改
在修改程式前，先讓 Claude 理解相關檔案與上下文。

### 4. 先測再修
優先執行測試，再根據結果修正問題。

### 5. 保持 `CLAUDE.md` 精簡
將專案規則與上下文寫得簡潔且明確，有助於長期維護。

### 6. 善用自動模式
遇到流程清楚、重複性高的工作時，可切換到自動模式減少手動干預。

## 結論

Claude Code 的核心價值在於：

1. 幫助使用者建立清楚的上下文  
2. 透過 Slash 指令快速操作  
3. 使用快捷鍵提升互動效率  
4. 以 agent / subagent 拆解大型任務  
5. 讓工具鏈直接參與實際開發工作  
6. 透過背景模式與自動化提升產能  

總結來說，**Claude Code 最有效的使用方式，是先規劃、再拆解、再執行，並善用指令、快捷鍵與 agent 協作。**
