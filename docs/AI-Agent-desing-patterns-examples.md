# AI Agent Design Patterns 中文整理

h2. 1. 單次輸出 Agent（Single-Shot Agent）

|| 項目 || 內容 ||
| 核心流程 | User Request → LLM → Final Answer |
| 主要特點 | 只做一次模型推理，不進入 agent loop |
| 優點 | 低延遲、低成本、架構簡單 |
| 缺點 | 不適合多步複雜任務、無工具迭代 |
| 適合場景 | FAQ 回答、客服話術摘要、文案改寫、資訊抽取、翻譯、簡單分類 |

h2. 2. 迭代式 ReAct Agent（Iterative ReAct Agent）

|| 項目 || 內容 ||
| 核心流程 | 目標 → 判斷下一步 → 選擇動作 → 執行 → 觀察結果 → 重複 |
| 主要特點 | 邊思考邊行動，會使用工具並根據結果調整 |
| 優點 | 能處理動態任務、可用工具、彈性高 |
| 缺點 | 延遲較高、token 成本高、需控制循環 |
| 適合場景 | 網頁搜尋助手、資料查詢助理、除錯助手、研究型問答、任務型 AI 助理 |

h2. 3. 規劃者-執行者 Agent（Planner-Executor Agent）

|| 項目 || 內容 ||
| 核心流程 | Planner 先產生計畫 → 拆分子任務 → 多個 Executor 執行 → 彙整結果 |
| 主要特點 | 將長期規劃與短期執行分離 |
| 優點 | 可處理複雜流程、可並行執行、可觀測性較好 |
| 缺點 | 架構更複雜、規劃錯會影響全局 |
| 適合場景 | 長篇研究報告、跨系統工作流、自動化營運流程、多步驟商業流程、資料分析任務 |

h2. 4. 自我反思型 Agent（Reflexive Agent）

|| 項目 || 內容 ||
| 核心流程 | 先生成初稿 → 自我批判 → 修正優化 → 檢查品質 |
| 主要特點 | 強調自我審查與反覆改進 |
| 優點 | 輸出品質較高、可減少明顯錯誤 |
| 缺點 | 成本與延遲增加、仍可能漏掉事實錯誤 |
| 適合場景 | 內容生成平台、程式碼生成與重構、產品文案優化、報告撰寫、需要高品質輸出的場景 |

h2. 5. 驗證門控型 Agent（Verifier-Gated Agent）

|| 項目 || 內容 ||
| 核心流程 | Agent 產出 → 獨立 Verifier 檢查 → 通過才執行 |
| 主要特點 | 加入外部驗證層，避免錯誤直接落地 |
| 優點 | 安全性高、可靠性高、適合高風險操作 |
| 缺點 | 延遲增加、驗證規則設計較複雜 |
| 適合場景 | 金流支付、交易指令、合規審核、權限操作、企業級自動化系統、醫療/金融風控 |

h2. 產品選型建議

|| 需求 || 建議模式 ||
| 快速回答或內容轉換 | 單次輸出 Agent |
| 需要查資料、動態決策、使用工具 | 迭代式 ReAct Agent |
| 任務很長、很多步驟、需要拆解協作 | 規劃者-執行者 Agent |
| 需要提高文字、程式碼、分析結果品質 | 自我反思型 Agent |
| 任務有風險，不能直接相信模型輸出 | 驗證門控型 Agent |

h2. 常見混合架構

|| 產品類型 || 常見組合 ||
| 客服助理 | Single-Shot + ReAct |
| 研究報告助手 | Planner-Executor + Reflexive |
| 企業自動化系統 | Planner-Executor + Verifier-Gated |
| 程式碼助手 | ReAct + Reflexive + Verifier-Gated |
| 金融操作代理 | Planner-Executor + Verifier-Gated + 人工確認 |

h2. 實務結論

* 先選最簡單能解決問題的模式
* 根據任務複雜度、風險、可靠性需求組合模式
* 高風險任務建議加上驗證層與人工確認
* 不要期待單一模式就能保證正確
* 需要記憶、守門與回饋機制，才能做出穩定的生產級 Agent
